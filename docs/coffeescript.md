# CoffeeScript browser execution

`COFFEESCRIPT` (alias `COFFEE`) runs the unchanged official CoffeeScript 2.7.0
browser compiler in a Worker. It compiles fresh `.coffee` or `.litcoffee` input
to JavaScript and executes the result through wasm-idle's JavaScript runner.
Compilation and execution stay in the browser. The separate compiler bundle
does not load SWC, and ordinary JavaScript/TypeScript bundles do not load CoffeeScript.

The editor includes CoffeeScript syntax highlighting and original CoffeeScript
compiler diagnostics. Its default file is `main.coffee`. Program arguments,
UTF-8 stdin/stdout, workspace data files, output limits, deadlines and cancellation
share the JavaScript execution contract. For example:

```coffee
fs = require 'fs'
values = (Number x for x in fs.readFileSync(0, 'utf8').trim().split /\s+/)
console.log values.reduce ((a, b) -> a + b), 0
```

`fs.readFileSync(0, 'utf8')` reads until terminal EOF. The JavaScript runner's
`fs.readLineSync(0)` convenience method reads one line without waiting for EOF.
The supported builtins are `fs`, `path`, `process` and `buffer`, with their existing
browser behavior. Arbitrary npm packages, external module imports, separate
CoffeeScript source-module compilation and the Node.js runtime are unavailable.
Runtime stack positions refer to generated JavaScript; compile errors refer to
the original CoffeeScript source. Debugging is unavailable.

Hosts may set `runtimeAssets.typescript.coffeeScriptModuleUrl` to a mirror of the
pinned `wasm-typescript/coffeescript.js` entry, or use the normal runtime `rootUrl`.
The Worker verifies its generated byte-size/SHA-256 receipt before importing it.

To rebuild this runtime only:

```sh
pnpm --dir runtimes/wasm-typescript build
pnpm sync:wasm-typescript
```

The normal static-runtime compression and asset-lock steps then update delivery
metadata. Run `pnpm test:browser:coffeescript` for real Chromium source compilation,
terminal stdin/EOF, diagnostics, Stop and recovery coverage.
