This release includes the changes merged after the 1.2.0 preparation in
`02ef9f76ff0705ec5422c91ddf431e64614d6d82`, through
`25e7d691b577bd310bcb9f67a50fddbf35553a18`.

| Packages                                                                        | Previous version  | Release version |
| ------------------------------------------------------------------------------- | ----------------- | --------------- |
| `wasm-idle`, core, debug, llvm-core, lsp, node, react, svelte, terminal and vue | 1.2.0             | 1.3.0           |
| `@wasm-idle/gcc`                                                                | First npm release | 1.3.0           |

The public SDK packages share the 1.3.0 version. The container package retains its
independent experimental version series; its patch release follows the updated SDK
dependencies. Private runtime workspaces remain outside the npm release.

## Changes

- Add `@wasm-idle/llvm-core/cross-clang` for browser-side C/C++ compilation to Linux
  x86-64 assembly, ELF objects and static executables with an explicitly supplied,
  receipt-verified Clang/GNU toolchain bundle
  ([PR #320](https://github.com/seo-rii/wasm-idle/pull/320)).
- Add the standalone `@wasm-idle/gcc` package, with a dedicated browser Worker API for
  real GCC and binutils cross compilation. Shared asset loading, archive reading and
  encoding helpers are exported from `@wasm-idle/core`; the GCC host depends on core
  independently of LLVM
  ([PR #321](https://github.com/seo-rii/wasm-idle/pull/321)).
- Export `compilePython` from `wasm-idle` to compile a Python source file to CPython
  `.pyc` bytes in an isolated Pyodide Worker without executing the source or loading
  its imports. Options include optimization, bytecode invalidation mode, cancellation
  and resource limits; results include Python version and bytecode format metadata
  ([PR #322](https://github.com/seo-rii/wasm-idle/pull/322)).
- Route LLDB console and diagnostic messages through dedicated debugger output events
  and the debugger log, keeping program stdout/stderr separate. Bound retained output
  and preserve partial lines across output events
  ([PR #323](https://github.com/seo-rii/wasm-idle/pull/323)).
- Refresh pinned dependencies, language-service integrations and regenerated runtime
  assets, including PHP, PostgreSQL, Prolog, SQLite and TypeScript
  ([PR #324](https://github.com/seo-rii/wasm-idle/pull/324)).

## Upgrade notes

Keep participating public SDK packages at 1.3.0. Applications importing
`wasm-idle/container` also need `@wasm-idle/container@0.2.1`, declared as an optional
exact peer of the root package. Install `@wasm-idle/gcc@1.3.0` explicitly to use GCC.

`DebugSessionEvent` now includes an `output` variant with `console` and `important`
categories. Update exhaustive event handlers to accept this event separately from
program output.

Clang and GCC cross compilation require independently built and qualified external
toolchain bundles with trusted manifest receipts. These npm packages contain host
code and types; applications provide compiler assets and download the generated ELF
artifacts. See the [Clang API documentation](../../packages/llvm-core/README.md) and
[GCC package documentation](../../packages/gcc/README.md) for supported profiles and
bundle qualification. The cross compiler APIs do not add an x86 executor to the browser
or enable an x86 playground target.

Python bytecode uses the selected Pyodide runtime's CPython format. Check the returned
`pythonVersion`, `cacheTag` and `magicNumber` before consuming a `.pyc` in another
Python runtime.

## Release preparation

Use a clean release checkout with dependencies installed and a complete runtime asset
tree. The release command checks npm version availability, synchronizes manifests and
the lockfile, regenerates the runtime asset lock, builds public packages, and verifies
packed installation, imports, types, size budgets and internal dependency versions:

```sh
pnpm release:npm -- --version 1.3.0 --container-version 0.2.1
```

When runtime assets are stored separately, append `--asset-root /path/to/prepared/static`.
The source must preserve all existing receipt paths; the generated lock is written only
in the release checkout. Review the resulting lock with the version changes.

Preparation does not publish packages and does not require npm authentication. A
separately authorized publish uses the same arguments with `--publish` after npm login.
The release script validates all 12 tarballs and publishes in dependency order.

Website deployment requires its own `pnpm run page:build` artifact and browser checks.
