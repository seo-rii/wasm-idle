# wasm-idle 1.4.0

This release includes the changes merged after the 1.3.0 source baseline
`25e7d691b577bd310bcb9f67a50fddbf35553a18`, through
`7f83ae66db2f7c98d82cc62064a414bcd4e9aff4`.

| Packages                                                                             | Previous version | Release version |
| ------------------------------------------------------------------------------------ | ---------------- | --------------- |
| `wasm-idle`, core, debug, gcc, llvm-core, lsp, node, react, svelte, terminal and vue | 1.3.0            | 1.4.0           |
| `@wasm-idle/container`                                                               | 0.2.1            | 0.2.2           |

The public SDK packages share the 1.4.0 version. The container package retains its
independent experimental version series; 0.2.2 refreshes its SDK dependencies without
changing its public API. Private runtime workspaces remain outside the npm release.

## Changes

- Expand GCC x86 compilation to qualified GCC 16.2 bundles while retaining GCC 13.3
  support. Add multiple translation units, explicit AVX2 and AVX2-with-FMA profiles,
  C executable libm linkage, shared read-only sysroot storage and reusable
  `bits/stdc++.h` precompiled headers
  ([#325](https://github.com/seo-rii/wasm-idle/pull/325),
  [#327](https://github.com/seo-rii/wasm-idle/pull/327),
  [#335](https://github.com/seo-rii/wasm-idle/pull/335),
  [#346](https://github.com/seo-rii/wasm-idle/pull/346)).
- Add an explicit experimental GCC 17 `wasm32-wasi` target alongside x86 output.
  Produce WAT, relocatable Wasm objects and WASI Preview 1 executables, with buffered
  stdin/stdout and qualified GNU C++ libraries, SIMD128, binary128 `long double` and
  `__int128` capabilities ([#328](https://github.com/seo-rii/wasm-idle/pull/328)).
- Add bounded in-memory WASI filesystem preopens and returned file contents,
  receipt-checked static object/archive link inputs, opt-in RTTI, DWARF debug
  information and GCC `.gcno`/`.gcda` coverage output
  ([#357](https://github.com/seo-rii/wasm-idle/pull/357)).
- Add separately qualified WASI profiles for relaxed SIMD, atomics, shared-memory
  Worker entries, local-exec TLS, modern Wasm C++ exceptions and embedded GNU C++20
  time-zone data. Shared TLS includes per-Worker storage and destructor cleanup;
  it does not provide pthreads or `std::thread`
  ([#371](https://github.com/seo-rii/wasm-idle/pull/371),
  [#372](https://github.com/seo-rii/wasm-idle/pull/372),
  [#373](https://github.com/seo-rii/wasm-idle/pull/373),
  [#374](https://github.com/seo-rii/wasm-idle/pull/374),
  [#375](https://github.com/seo-rii/wasm-idle/pull/375)).
- Add opt-in GNU `std`/`std.compat` modules with verified Wasm-host BMIs and
  initializer archives. Qualified bundles also expose the bounded C++26
  `<debugging>` function profile; this does not promise general C++26 library
  support ([#368](https://github.com/seo-rii/wasm-idle/pull/368),
  [#377](https://github.com/seo-rii/wasm-idle/pull/377)).
- Run Java 25 compact source files and static or instance `main` methods with or
  without `String[]` arguments through the real javac/TeaVM compiler. Preserve
  constructor behavior, exact overload selection, original exception source frames
  and warm compilation reuse. Bundle the metadata reader without adding an ASM
  production dependency; restore pinned javacs JDK downloads
  ([#378](https://github.com/seo-rii/wasm-idle/pull/378),
  [#379](https://github.com/seo-rii/wasm-idle/pull/379)).
- Add experimental Scala 3/Scala.js execution through the real browser compiler and
  linker, with multiple workspace files, program arguments, preloaded stdin and a
  fresh execution Worker for each run
  ([#355](https://github.com/seo-rii/wasm-idle/pull/355)).
- Upgrade Zig execution and its language server to 0.17.0 and add source debugging
  through Zig LLVM bitcode, browser Clang/LLD and LLDB/WAMR. Display byte-slice
  previews, optionals and error unions from native DWARF values
  ([#339](https://github.com/seo-rii/wasm-idle/pull/339),
  [#341](https://github.com/seo-rii/wasm-idle/pull/341),
  [#350](https://github.com/seo-rii/wasm-idle/pull/350)).
- Inspect directly declared instance fields of ordinary Java source classes without
  invoking getters, including paged object/array values, aliases and cycles. Reduce
  Python debugger setup/trace overhead and add a normalized-header Python bytecode
  output mode ([#349](https://github.com/seo-rii/wasm-idle/pull/349),
  [#351](https://github.com/seo-rii/wasm-idle/pull/351),
  [#347](https://github.com/seo-rii/wasm-idle/pull/347)).
- Load runtime receipts lazily, share concurrent verified asset requests, avoid
  duplicate digests and overlap Worker/compiler preparation. Fix editor tab state,
  ZIP integrity checks, artifact-view validation, cancellation during container
  admission, Clang stdin handling and C# runtime errors/stdin.
- Refresh pinned Go 1.26.10, TinyGo 0.43.0, OCaml 5.5.2, C3 0.8.5_1 and TeaVM 0.16.0
  runtimes, including upstream TeaVM bootstrap changes.

## Upgrade notes

Keep participating public SDK packages at 1.4.0. Applications importing
`wasm-idle/container` also need `@wasm-idle/container@0.2.2`, declared as an optional
exact peer of the root package. Install `@wasm-idle/gcc@1.4.0` explicitly to use GCC.
Update exhaustive language handlers for the new `SCALA` language identifier.

Compiler/runtime assets remain separate from npm host packages. GCC features require
the corresponding verified manifest capabilities and qualified external bundles;
the profiles cannot be combined arbitrarily. Shared-memory execution requires
cross-origin isolation and module Workers; C++ exceptions require modern Wasm EH
engine support. Standard modules require the initial `gnu++23`/O2 scalar executable
profile. See the [GCC API documentation](../../packages/gcc/README.md) for exact
request, runtime and receipt requirements. x86 artifacts remain downloads for an
external execution host.

Java 25 entry-point support applies to Run and does not qualify compact-source
debugging or change the Java language server's Java 17 API model. TeaVM class-library
compatibility still applies. Java object inspection remains read-only; unsupported
objects retain an opaque display. See the
[debugger support matrix](../debugger-language-support.md).

Scala requires the browser's WasmGC/JSPI facilities and the pinned upstream asset
graph. Its initial profile supports preloaded input ending in EOF, not interactive
input, JVM-only libraries, arbitrary dependencies, debugging or a language server.
Consult the [Scala runtime documentation](../../runtimes/wasm-scala/README.md) and
its provenance requirements before redistributing a local asset mirror.

Python's `invalidationMode: 'normalized'` clears the source-dependent `.pyc` header
fields while preserving the CPython code payload. Check the returned Python version
and magic number before consuming it in another runtime.

## Release preparation

Use a clean release checkout with dependencies installed and a complete runtime asset
tree. The release command checks npm version availability, synchronizes manifests and
the lockfile, regenerates the runtime asset lock, builds public packages, and verifies
packed installation, imports, types, size budgets and internal dependency versions:

```sh
pnpm release:npm -- --version 1.4.0 --container-version 0.2.2
```

When runtime assets are stored separately, append `--asset-root /path/to/prepared/static`.
Preserve every existing receipt path and review the generated lock with the version
changes. Commit the release preparation before the publish command's clean-checkout
validation.

Preparation does not publish packages or require npm authentication. An authorized
publish uses the same arguments with `--publish` after npm authentication. The release
script validates all 12 tarballs and publishes in dependency order; `--resume` accepts
an existing version only when its registry hashes match the verified tarball.

Website deployment uses its own `pnpm run page:build` artifact and browser checks.
