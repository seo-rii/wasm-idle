# wasm-idle 1.2.0

This release brings the changes merged since the repository recorded the 1.1.2 release
in `7e69645a0acc1ef2ad4e5c025f9875eb37217b81`. The preparation starts from
`8c9dc157fc6551588b2301d6e8ef0f69d1e223bf`, including the final LSP review fixes in
[PR #319](https://github.com/seo-rii/wasm-idle/pull/319).

| Packages                                                                        | Previous version | Release version |
| ------------------------------------------------------------------------------- | ---------------- | --------------- |
| `wasm-idle`, core, debug, llvm-core, lsp, node, react, svelte, terminal and vue | 1.1.2            | 1.2.0           |
| `@wasm-idle/container`                                                          | 0.1.1            | 0.2.0           |

The container package keeps its independent experimental version series. Private runtime
workspaces are not npm release packages.

## Changes

- Add browser LSP providers using upstream implementations for Java, PostgreSQL, PHP, Fennel,
  Forth, Bash, Grain, C3, COBOL, ReScript, V, Lean 4 and Nim. Java uses javacs and the OpenJDK
  compiler compiled with TeaVM. Providers are available through `@wasm-idle/lsp` and the playground.
- Expand source debugging with LLDB/WAMR for Objective-C, Objective-C++ and V; Java source hooks
  with local values, arrays and read-only snapshot expressions; Lua MobDebug; and Ruby TracePoint.
  These enabled backends run without browser extensions.
- Improve debugger inspection with persistent variable trees, paged values, stop snapshots,
  hover inspection and richer breakpoint controls where supported. Fix frame selection,
  scope shadowing, repeated-line Python stops, Go instrumentation and bounded Ruby/Rust inspection.
- Add per-language compiler settings saved with workspaces and included in shared links and
  backups. C/C++ standards and flags also configure clangd. Normal C/C++ execution supports
  the SSE-through-AVX2 subset provided by pinned Emscripten compatibility headers, including
  `<immintrin.h>` and `<x86intrin.h>`.
- Expose the optional `wasm-idle/container` execution host for applications that supply their
  own UI, worker and asset configuration.
- Improve repeated execution and editor responsiveness through verified module reuse,
  incremental C/C++ builds, changed-file workspace synchronization, Rust checking profiles,
  Java output batching and coalesced Python LSP work.
- Preserve workspace edits across browser tabs and apply workspace file batches atomically.
  Fix empty-run completion, static-worker retries, Python UTF-16 positions and TypeScript
  completion replacement.
- Fix Lean import-restart ordering and request settlement, Forth edits before document open,
  C3/V producer-cache invalidation, per-file V asset limits and cached ReScript deployment metadata.

## Upgrade notes

Keep the participating SDK packages at 1.2.0. Install `@wasm-idle/lsp@1.2.0` explicitly when
using its editor providers. Applications importing `wasm-idle/container` also need
`@wasm-idle/container@0.2.0`; the root package declares it as an optional exact peer.

Runtime assets remain separate from npm host packages. New LSPs need their pinned external
runtime distributions. See the [LSP package documentation](../../packages/lsp/README.md) and
[runtime asset cache documentation](../runtime-asset-cache.md) for configuration and receipt checks.

- Java LSP supports plain source projects with supplied Java 17 APIs, without build-system
  inference, external dependencies or annotation processors.
- Lean LSP supports one active document and `Init`, requires cross-origin isolation/pthreads,
  and does not provide Lake, Mathlib, `Std` or a project-wide index.
- Bash does not include ShellCheck/shfmt. V does not provide compiler diagnostics or formatting
  in its LSP. C3 supplies lexer diagnostics. ReScript excludes npm compiler dependencies,
  namespaces, PPX and custom compiler flags.
- SIMD support applies to normal execution. LLDB/WAMR remains scalar; native x86 assembly,
  CPU-specific intrinsics, FMA and AVX-512 are outside the compatibility profile.
- Debugger support remains specific to each backend. Java expressions inspect read-only
  snapshots; general objects remain opaque. JavaScript/TypeScript debugging remains disabled.
  See the [debugger support matrix](../debugger-language-support.md) for supported operations.

## Release preparation

Use a clean release checkout with its dependencies installed. The default command synchronizes
the versions, checks registry availability, regenerates the asset lock, builds the public
packages, and verifies packed installation, imports and dependency metadata:

```sh
pnpm release:npm -- --version 1.2.0 --container-version 0.2.0
```

Preparation does not require npm login and does not publish packages. When the complete runtime
asset tree is stored separately, supply `--asset-root /path/to/prepared/static`; the generator
reads that directory and writes the release lock in this checkout. A sparse or incomplete
asset tree is not a valid release input. The lock must retain existing runtime receipt paths.

Before publishing, review the generated lock and version changes, commit the release preparation,
and require the release checks to pass. A separately authorized publish uses the same arguments
with `--publish` and requires npm authentication. Existing versions can only be resumed when
their registry hashes match the freshly verified tarballs.

Website deployment requires its own complete `pnpm run page:build` artifact and the repository's
browser checks. npm package validation does not qualify a new website build or deploy it.
