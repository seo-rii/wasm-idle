# Original Icarus Verilog browser toolchain

This runtime uses the genuine Icarus Verilog preprocessor (`ivlpp`), compiler
(`ivl`) and simulator (`vvp`). The six upstream JavaScript and Wasm artifacts
are retained byte for byte from VeriSim commit
`ab0ff3862a8cf8c6535117a64d370c4bf263042f`. Its original Icarus source is commit
`c7530dbcc186de2f21eacde14fd28061b885924c` (14.0 development version).

`upstream.json` pins each artifact's byte count and SHA-256. The original
`upstream-build.sh` and `iverilog-wasm.patch` document rebuilding the three
modules using Emscripten 6.0.0. The port links the normal VVP code generator and
system tasks statically, because browser modules cannot load native plugins.

From the repository root:

```sh
node scripts/sync-wasm-verilog.mjs --download
node scripts/sync-wasm-verilog.mjs --check
```

Normal page builds verify the committed payload; they do not download or compile
a toolchain. For a source rebuild, use an isolated directory, retain the pinned
Icarus commit and platform patch, and run `bash upstream-build.sh`. The original
script installs a local Emscripten SDK and needs git, make, autoconf, gperf,
bison, flex and Python 3.

The browser host passes source and workspace files through private MEMFS,
preprocesses all `.v`/`.sv` files together, compiles with the fixed Verilog 2012
profile, then runs `vvp -i -n -msystem` with the generated bytecode. The standard
unbuffered option preserves final partial lines; `$stop` ends the batch run.
The normal static
system-task registration avoids requesting native compiler plugins.

The worker verifies upstream artifacts before changing only the Wasm memory
maximum to enforce the execution limit. Parsing, elaboration, simulation and
system-task semantics remain the upstream implementation. `LICENSE.iverilog`
and `LICENSE.emscripten` preserve the compiler/VM and runtime licensing.
