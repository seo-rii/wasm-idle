# APECode on Pyodide

This runtime runs the original [seo-rii/apecode](https://github.com/seo-rii/apecode)
**0.1.0** interpreter at commit `c7ae98d3dfc1713ecc800422a4c815628776e1e2` on
the existing Pyodide browser runtime. Its own lexer, parser, robot state machine,
built-in states and input handling execute the program. The browser calls the
original `apecode.cli.run_source` API, which is the implementation used by the
upstream CLI's `--run` option.

`vendor/apecode-c7ae98d3dfc1713ecc800422a4c815628776e1e2.tar.gz` is the unchanged
7,277-byte upstream archive. Its SHA256 is
`0ff71e149ec49a94211bb44b6a3d55e1290acb1387ca4f5f76a8f42f568ae629`.
All three Python package files in the wheel are byte-for-byte identical to this
archive. Only standard wheel packaging metadata is generated by setuptools. The
package is dependency-free and its wheel is 7,484 bytes with SHA256
`30aecb8eeff9a40cd55bb5fe5c18104f6c8308bdba9e71ac0b95d077badae30c`.

The pinned upstream archive contains no license file or project license
declaration. `UPSTREAM-LICENSE-NOTICE.txt` records that status, including the source
and revision, and is distributed with the wheel. It does not assign a license to
the original source. The integration uses the repository owner's requested
APECode runtime; the build receipt retains the upstream license status.

The worker fetches the wheel from the configured local asset path, checks its
code-pinned version, file name, size and SHA256 before extraction, and verifies
`apecode.__version__` after importing the genuine `run_source` API. A dedicated
worker installs one language extension and rejects changes to its language.
Browser execution does not fetch Python packages from a package registry.

## Execution and I/O

The worker writes the unchanged user program to a private UTF-8 source file at
`/tmp/__wasm_idle_apecode__/<activePath>`, then calls the original API with that
source and Python's real `sys.stdin`, `sys.stdout` and `sys.stderr` streams. The
private file is removed on completion and failure. Preparation installs the
runtime without scanning APECode source as Python or parsing/executing the user's
program. Python debugging is unavailable for APECode.

The original input reader consumes stdin until EOF and extracts signed decimal
integers. Input starts with a test case count, followed by each case's rock count
and rock weights. Its state machine preserves calls, repeating state bodies,
conditional branches, returns, both grippers, tilt comparisons, movement,
remember/recall and trace output. Normal output reports each resulting rock field,
using `-` for empty positions. Python integers retain arbitrary precision.

Pyodide's file-descriptor APIs receive UTF-8 bytes without an added newline, and
terminal input can arrive in several chunks before EOF. EOF persists until the
next run. The original interpreter writes final results and its special signature
case through `stdout.buffer` when available. Separate streaming UTF-8 decoders
handle stdout and stderr; NUL bytes remain NUL and malformed UTF-8 bytes appear as
U+FFFD in the text terminal. Both Python streams and the decoders are flushed when
the call ends. Trace output keeps the original Python stream behavior.

The original API emits its diagnostics to stderr and returns a status code. A
nonzero status fails the playground run after preserving the upstream diagnostic.
Each API call creates a fresh original interpreter and robot state. Cancellation,
timeouts and output limits use the dedicated host worker lifecycle.

## Rebuild and verify

From the repository root, with `uv` available:

```sh
node scripts/sync-wasm-apecode.mjs --check

TMPDIR=/data UV_CACHE_DIR=/data/uv-cache node scripts/sync-wasm-apecode.mjs
```

`--check` verifies the committed original source archive, upstream license notice,
wheel and build receipt without network access or a Python toolchain. Rebuilding
uses the vendored source archive, a `setuptools==84.0.0` build constraint and
`SOURCE_DATE_EPOCH=315532800`. The result must match the pinned wheel before any
runtime artifact is written. `uv` may fetch the build backend when it is absent
from the developer's cache. Temporary files are removed after the build; the
receipt contains no current timestamp or machine-specific path.
